### 侧栏文件夹

### AI 多文档上下文
- 会话级作用域：`AiSession.contextPaths?: string[]` 存进 sessions.json，切会话各自独立。
- 预算滑块 8k–128k，持久化到 `localStorage['inkwell.ctxBudget']`。
- `lib/ai.ts` 新增 `packContextFiles()`：先按 `charBudget/n` 均分（每篇不低于 1200 字），再把剩余额度补给被截断的篇目；`charBudget = budget*1.45*0.8`（中文 0.68 token/字）。
- prompt 结构：`<context-files><file path title>` + `<library>`（仅当用户挑过文档时才注入全库清单，普通问答不浪费）+ `<selection>`。

### AI 工具调用（关键）
- `main/ai.ts` 拆成 `streamOnce()` + `runChat()`：`streamOnce` 只负责一轮 SSE，返回 `{text, reasoning, toolCalls, usage}`；`runChat` 管工具循环（最多 4 轮），把 assistant(tool_calls) 与 tool 消息回灌后重新请求。
- `delta.tool_calls` 是按 `index` 增量下发的，`function.name` 和 `function.arguments` 都要**字符串拼接**，不能覆盖。
- 兼容降级：400 且 body 含 `stream_options` → 去掉用量统计；含 `tool|function|parallel` → 去掉 tools，发 `ai:tool{status:'unsupported'}` 让前端提示一次。
- 事件 `ai:tool {reqId,name,args,status,preview}`，前端显示「读取 xxx 中…」并把「读取了 xxx」记进 `AiSessionMessage.tools`。
- `makeEmitter` 加 `base` 参数：多轮时第二轮只发增量，但前端是覆盖式 patch，所以要拼上前面几轮已输出的文本。

## 08:10 「插入到光标处」

### 改了什么
- `App.tsx`：新增 `caretRef`（`{path,start,end}`）+ `rememberCaret`，挂在 textarea 的 `onFocus/onKeyUp/onMouseUp/onSelect`。原来点 AI 面板会让 textarea 失焦，`selectionStart` 虽仍在，但从未聚焦过时是 0 → 会静默插到文首。
- 插入位置优先级：记忆光标（同 path）→ 当前聚焦的编辑器 → 兜底追加文末（提示里说明，不静默）。
- `composeInsert()` + `BLOCK_HEAD`：块级内容（多行/标题/列表/引用/表格/代码块/图片/HTML/:::）自动补空行；行内内容（Tab 两个空格）原样插；有选区时精确替换、不加空行。
- 拆成三个动作：`insertAtCaret`（插入到光标处，带「已插入到第 N 行」提示 + 手动 scrollTop 让插入点进视野）、`appendText`（文末）、`insertAtCursor`（Tab/粘贴图片用，静默）。
- `AiPanel`：动作行改为 复制 / **插入到光标处**（accent 色 `.is-primary`）/ 文末 / 替换全文 / 新文档 / 重试。

### 验证（CDP 实测）
- 光标在「第一行」行尾插入 → `# 插入测试\n\n第一行\n\n## 结论...\n\n第二行\n`，空行隔离正确，caret 落在插入块末尾，编辑器重新聚焦，提示「已插入到第 8 行」。
- 选中「第二行」再插入 → 精确替换，无多余空行，提示「第 13 行」。
- `location.reload()` 后不碰编辑器直接插入 → 追加文末 + 「已追加到文末 · 在正文点一下可指定插入位置」。
- 清场：删 `_insert-test.md`、还原 sessions.json/config.json（lastDoc 回「欢迎使用 Inkwell.md」）、删临时 CDP 脚本。

### 注意
- 后台跑 electron 必须用 `run_in_background`，`&` 起的进程在 shell 结束时会被杀（表现为 CDP 端口 ECONNREFUSED）。

## 23:50 （11-01 补记）AI 写能力

### 设计
- **改已有文档不直接落盘**：`edit_doc` 只生成提案（`pendingWrites` Map，存 before/after/add/del），通过 `ai:write` 事件推到渲染层；用户点「应用」才走 `ai:write:apply` 写盘。新建文档 `create_doc` 直接生效（新增文件零风险），推 `ai:doc-created` 让侧栏刷新。
- 提案 = 最小编辑：`edits[{old,new}]`，old 必须逐字符唯一匹配，0 处或多处都返回错误文本让模型重读；另有 `append` 追加。
- 版本校验三道：apply 前 flushSave → 渲染层比对 `contents[path] === before` → 主进程再读盘比对 `current === before`，任何一道不符就提示「提案作废」，绝不覆盖用户手改。
- 同一文档新提案到达时旧提案自动作废（`ai:write:drop`）。
- 卡片标题取首个 H1（没有才用文件名）。

### 落点
- `src/main/ai.ts`：VAULT_TOOLS 5 个工具、`execTool(name, args, {vault,send,reqId})`、`pendingWrites`、`ai:write:apply/discard`。
- `src/main/index.ts`：VaultAccess 补 `write` / `create`（create 走 `uniqueName` + 非法字符清洗）。
- `preload`：`aiApplyWrite` / `aiDiscardWrite` / `aiOnWrite` / `aiOnWriteDrop` / `aiOnDocCreated`。
- `App.tsx`：`writes` 状态、`applyWrite/discardWrite/previewWrite`、diff 增加 `writeId` 分支。
- `AiPanel.tsx`：输入框上方 `.ai-writes` 卡片（看 diff / 应用 / 忽略），工具标签补 create_doc / edit_doc。
- `lib/ai.ts` 提示词加「# 改文档」段：只在明确要求时写、先 read 再改、最小改动、不能删文档、改完一句话说明。

### 验证（mock 模型 + CDP）
- 改文档 → 卡片「建议修改《写测试》 +1 −1」；看 diff 显示 `−旧的内存值 / +新的内存值（16G）`；应用后落盘、编辑器同步、`Ctrl+Z` 入口就绪。
- 冲突：提案后手改正文再应用 → 提示「文档在这期间被改过，这条提案作废了」，用户手改内容保留，磁盘未被覆盖。
- 新建：`create_doc` 生成 `AI 新建的笔记.md`，侧栏即时出现。
- 清场：还原 models/sessions/config，删 `_write-test.md`、`AI 新建的笔记.md`、mock 与 CDP 脚本。
