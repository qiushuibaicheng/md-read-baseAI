## 链接解析改为严格路径 + 移动改名自动改写链接

用户判断「索引兜底弄巧成拙」，要尊重文件里写好的路径；并要求文件移动后链接自动更新。

### 1. 删掉四步兜底（src/main/links.ts）

原来是「相对目录 → 库根相对 → 全库唯一文件名 → 按显示文字猜标题」。第四步是罪魁：
`[限流策略](限流策略.md)` 库里没这个文件，靠显示文字命中标题为「限流策略」的
`规则/限流阈值.md`，界面显示成功，掩盖了链接本身写错的事实。

现在只认「相对当前目录」和「`/` 开头算库根」，找不到就 broken。顺带删掉 byName / byTitle
两个查找表和 normTitle，它们只服务于已删除的兜底逻辑。

示例库 22 条链接：严格 16 命中 / 6 失效；保留唯一文件名回退 17/5。只多救 1 条却要保留
猜测，不划算，所以全删。

### 2. 撤回 wiki 支持

用户中途改主意（做完渲染层后说「不用支持 wiki」）。没有留半支持状态：索引侧原本解析
`[[ ]]`，如果只撤渲染层，会变成「AI 看得到关系、人看不到」，违反人机同源。所以
`WIKI_LINK` 正则、`RawEdge.wiki` 等字段、markdown-it 的 `ink_wiki` 规则、`.wiki-link`
样式全部移除。

### 3. 新增 src/main/relink.ts

`LinkIndex` 的边增加 `col`（行内字符偏移），因为同一行可能有多条链接，只靠行号定位会改错。
改写流程：

- 移动前 `snapshotInbound()` 快照入链（移动一完成旧路径就解析不到，那些边会退化成断链）
- 物理 rename
- 按 old→new 映射重算相对路径，保留作者原风格：`./` 前缀、`/` 库根、有没有 `.md`、有没有 URL 编码
- 逐行按 col 精确替换，位置对不上时只在整行唯一出现才敢动，否则记 skip
- 同文件多处改动从右往左替换，避免偏移漂移
- 每批 12 个文件并发

踩坑：`[x](./限流.md)` 移到别的目录时，`posix.relative` 返回 `../归档/限流.md`，
直接拼 `./` 会得到 `./../归档/限流.md`。修成「rel 以 `..` 开头就不加 `./`」。

### 4. 接线与提示（src/main/index.ts）

`moveDocTo` / `moveFolderTo` / `doc:rename` 三个入口接上；文件夹移动时把里面每篇文档
批量放进 moves 映射（引用方自己也可能在移动集合里）。改完 `linkIndex.invalidate()`，
通过 `vault:relinked` 事件告诉渲染层改了几处、影响哪些文件。

渲染层收到后：没打开的文档清缓存，打开且没有未保存内容的重新读回来，有未保存内容的
提示「待手动刷新」（防覆盖）。toast 文案「已更新 N 处链接」。

## 修：AI 移动文档不改写链接（moveEntryAny 漏接 relink）

用户配好模型后要求实测「索引还有没有用」。造了三篇互链的示例库
（`事故/502-网关超时.md` ↔ `规则/限流阈值.md`、`值班/值班表.md`，外加一条故意断链
`[限流策略](限流策略.md)`），通过 CDP 在真实界面提问。

第一轮正常：`get_links ×2 → search_docs → list_tree`（4 步），回答准确列出 3 条引用
（13/17 行 ok，21 行断链），结论「移动只会影响 1 篇」。索引读路径没问题。

第二轮让 AI 自己 `move_entry` 移动 `规则/限流阈值.md`，暴露漏洞：文件挪过去了，
但《502》第 13 行仍是 `../规则/...`，直接变断链。原因不是索引，是接线：
界面走 `moveDocTo` / `moveFolderTo`，AI 的 `move_entry` 走 `moveEntryAny`，
两条独立实现，relink 只加在了前者。

修法与复测：`moveEntryAny` 里 rename 之前取 `snapshotInbound()`，文件夹时展开内部文档，
rename 后 `applyRelink`。复测双向往返：移到 `归档/` → 第 13 行变 `../归档/限流阈值.md`，
toast「已更新 1 处链接」；移回 `规则/` → 又改回 `../规则/限流阈值.md`。

教训：同一个语义（移动）有三套实现时，新加的能力（relink）必须三处都接，
否则 AI 与人类看到的结果不一致——这类「工具与界面走不同代码」的漏洞，只有真跑
一次 AI 才会暴露。

## 索引触发点审计（未修，留待决定）

问题：「哪些时刻该更新索引却没有做到」。

已确认的事实：
- 真正 build 的只有 `sync()`；`invalidate()` 只打脏标记；TTL 1500ms 过期后任何查询也会重建，
  所以索引不会永久陈旧（唯一例外见下），最坏陈旧 = watcher 600ms / 无 watcher 时 1.5s 内。
- 正文永远实时读盘（`read_doc` / `search` 走 fs），陈旧的只有标题、行数、链接边。

三个缺口：
1. `folder:rename`（index.ts:915）右键重命名文件夹：不 relink、也不 invalidate。
   外部指入该文件夹的链接静默断掉，且无提示。与上次 `moveEntryAny` 同一类问题。
2. watcher 丢弃 filename（index.ts:1062，`watch(root,{recursive:true}, () => ...)`）：
   每次改动只能「全库标脏」，走 mtime/size 增量判定。当 mtime 与 size 都没变
   （同步盘保留时间戳 / FAT 2 秒粒度 / SMB 缓存 / 解压还原）时内容不会更新，
   且 `sync(true)` 也救不回——build 的增量判定不受 force 影响。已用探针复现：
   「全库标脏后」和「force 之后」标题仍是旧的，只有 `invalidate('a.md')` 才对。
3. `doc:write` / `create` / `import` / `delete` / `folder:delete` 无显式 invalidate，
   全靠 watcher + TTL 兜底。

其他：`relinkAfterMove` 的 catch 全吞（失败无 toast）；`startVaultWatch` 的 catch 空实现；
`sync(true)` 在 build 进行中被短路；外部重命名导致的断链不会自动修；
`config:set` 能改 vaultPath 却不 setRoot（当前 UI 不走，属埋雷）。

探针：`.tmp/audit.cjs`、`.tmp/audit2.cjs`、`.tmp/bench.cjs`（1200 篇冷建 157ms / 增量 24ms）。

## 第一梯队体验问题：撤销 + 移动后路径同步（已修并验证）

用户要求：撤销必须有；先修第一梯队。撤销入口定在 AI 对话面板（一轮结束后可撤）。

实现：
- 新增 `src/main/history.ts`：事务栈（30 步，内存态）。三类事务 move / write / create，
  每条带 reqId，AI 面板按 reqId 整轮倒序回退。冲突保护：当前内容 ≠ 记录的 after 就只还原位置。
  单条快照上限 400KB（超过只还原位置不还原正文）。删除不入栈（trashItem 无跨平台还原接口）。
- `relink.ts` 的 `applyRelink` 多返回 `snapshots`（每个被改写文件的 before/after 全文），
  让「移动 + 它触发的链接改写」合成一个可逆事务。
- `main/index.ts`：moveDocTo / moveFolderTo / moveEntryAny / doc:rename / folder:rename 全部
  recordMove，并新增 `vault:moved` 事件（旧路径→新路径）。
- 渲染层 `onVaultMoved` → `remapPaths`（现在返回搬动后的待存路径）→ 对新路径 flushSave。
  这修掉了「AI 移动正打开的文档后，自动保存会把旧目录重建出来变成两份」的数据分叉。
- AI 面板：`ai:done` 时查 `history:info(reqId)`，有记录就渲染「这次动了 N 处：… 撤销」，
  撤销后变成「这次操作已撤销」。用户在侧栏移动/改名的 toast 也带「撤销」按钮（停留 6s）。
- 顺手：监听 `ai:doc-created`，AI 新建文档立刻出现在侧栏。

验证（临时库 C:/tmp/inkwell-undo + CDP 真机）：
- AI 移动当前打开的文档后编辑并等待自动保存 → 新路径有内容、旧路径没有副本。
- AI 面板撤销：移动回退（restored 2：1 次 rename + 1 处链接正文）、新建文档进回收站。
- toast 撤销：侧栏改名 限流阈值→限流阈值v2，链接改写，点撤销后文件名与链接都还原。
- 冲突保护：移动后手工改 502.md，撤销返回 skipped=1、note「只还原了位置」，正文没被覆盖。
