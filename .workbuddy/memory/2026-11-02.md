## 01:05 侧栏排序 / 文件夹拖动 / 新建位置 / 文件夹行视觉

### 三个反馈对应的改动
1. **新建文件夹总落在「1」下面** —— 原因：`＋` 菜单把 `activeDir`（当前文档所在目录）当默认目标。改成两组菜单：默认根目录，另有「新建到『1』」一组，位置显式可见。
2. **文件夹行太小** —— `.folder-row` 从 `padding:5px 8px / 12.5px` 提到 `min-height:38px / 13px / weight 500`，计数改成胶囊、0 不显示，图标 15px 并按展开状态切换 `folder-open`。顺手把 `.doc-meta` 设成单行省略（原来长文件名会折成三行，文档行高 47→74 忽高忽低，也是"文件夹显得小"的一半原因）。
3. **只能拖进文件夹，不能排序、不能拖文件夹** —— 侧栏树重构为「每个目录一份混排 entries（文件夹 + 文档）」，拖拽统一走 `vault:arrange`。

### 排序怎么存的
- `config.order: Record<目录相对路径, 条目相对路径[]>`，文件夹与文档混排；没登记的条目排在后面，按「文件夹优先 + zh 名称」补位。
- 拖拽落点由**坐标**算：文档行上下半 → 插前/插后；文件夹行上 28% / 下 28% → 插前/插后，中间 40% → 移入。**在 drop 事件里重新算一次**（不要读 dragover 存的 state，React 渲染时序会让它为空）。
- 落点用 `.drop-line` 插入线 + 圆点表示；文件夹中部悬浮用 `.is-drop` 高亮。
- `vault:arrange({kind, path, targetDir, index})` 在主进程一次完成「跨目录移动（doc/folder）+ 插入排序表」，避免拖完顺序又被字母序打回。文件夹移动会级联改写 order 的键与值、`openTabs`、`lastDoc`。
- 防呆：不能拖进自己 / 自己的子目录；目标同名会报错。

### 顺手修的
- 渲染层 `config.order` 只有在 `config:changed` 时才更新，而新建/改名/删除只改主进程的 order → 新建的文档掉到列表末尾、改名后也会跳到末尾。加 `notifyConfig()` 在这些位置推送。
- 新建文档/文件夹时 `unshiftOrder` 插到所在目录最前面（符合「刚建完就看得到」）。
- 删除时 `dropFromOrder` 顺带摘掉排序表项，避免无限膨胀。
- `App.tsx` 抽出 `remapPaths(from, to)`：标签/正文缓存/脏标记/待存/pending/active/光标/AI 提案/撤回快照一起搬，移动与改名共用；原来只处理了 tabs 与 contents。
